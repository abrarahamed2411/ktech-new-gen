6. SEARCH ICON SIZING & CARD TEXT OVERFLOW RESOLUTION (2026-11-08)
--------------------------------------------------------------------------------
Identified and resolved two critical visual presentation issues reported during browser inspection:

1. Huge Search Icon on Products & Categories Pages:
   - Root Cause:
     * The inline `<svg viewBox="0 0 24 24">` elements in `products.html` and `categories.html`
       lacked hardcoded HTML `width` / `height` attributes and inline styles.
     * In standard SVG specifications, an SVG without explicit attributes expands to 100% of
       its container width. If browser cache delays stylesheet application or serves an older
       CSS revision, the SVG blows up to the full width of the screen (giant black circle).
   - Solution:
     * Added hardcoded attributes: `width="18" height="18" viewBox="0 0 24 24"`.
     * Added defensive inline styles: `style="width:18px!important;height:18px!important;max-width:18px!important;max-height:18px!important;position:absolute;left:14px;top:50%;transform:translateY(-50%);fill:#80948c!important;pointer-events:none;"`.
     * Embedded fallback `.filter-bar` and `.search-input-group` CSS directly into `<style>`
       blocks in `<head>` of both `products.html` and `categories.html`.
     * Updated stylesheet cache-busting query parameter across all 13 HTML files to `/styles.css?v=3`
       forcing browsers to invalidate stale CSS caches immediately.

2. Product Card & Category Card Text Overflow:
   - Root Cause:
     * In `styles.css`, an overly broad rule `.category-card a { white-space: nowrap; }` was
       applying `white-space: nowrap` to ALL anchor tags inside cards, including the product
       title links (`<h3><a ...>`) and category title links.
     * This prevented multi-word product titles from wrapping to a second line, forcing long
       titles (e.g. "KTECH Professional 5-Piece Tri-Ply Stainless Steel Cookware Collection",
       "KTECH 750W Heavy Duty Mixer Grinder with 3 SS Jars") to overflow horizontally beyond
       the card boundary and get clipped.
   - Solution:
     * Scoped `white-space: nowrap!important` strictly to `.category-card .enquire-card-link`
       and `.category-card .card-bottom > a`.
     * Added explicit wrapping rules to `.category-card h3` and `.category-card h3 a`:
       `white-space: normal!important; overflow-wrap: break-word!important; word-wrap: break-word!important; word-break: normal!important; line-height: 1.35!important; display: block!important;`.
     * Added `overflow: hidden; min-width: 0; box-sizing: border-box;` to `.category-card`
       and `.card-bottom` containers.
     * Updated `script.js` `renderCards()` template to apply these rules to dynamically
       generated cards on Homepage, Categories, and Products pages.
     * Re-captured browser screenshots confirming all product titles wrap cleanly across
       2–3 lines with zero truncation or horizontal card overflow.
