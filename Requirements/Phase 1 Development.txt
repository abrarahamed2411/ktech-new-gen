Prepared for OpenAI Codex

# Premium Product Catalogue & Enquiry Website

A complete responsive website for KTECH Home Appliances with seven main navigation sections, a structured product catalogue, individual product detail pages, bulk enquiry management, store information, blogs, and a content management dashboard.

## 1. Website structure

The website must work as a product discovery and lead-generation platform, not an e-commerce checkout platform.

Primary customer journey

Home

Categories

Subcategories

Products

Product Details

Request Quote / Enquire

The seven primary navigation items will be Home, Categories, About Us, Bulk Solutions, Our Stores, Blogs, and Contact.

## 2. Approved design direction

Mint, teal, white and deep green

Soft gradients, elegant curves and subtle gold accents

## Beautiful Kitchens.

## Better Living.

Playfair Display headings + DM Sans body

The existing design references use a premium mint-green and white interface, soft shadows, rounded product cards, teal CTA buttons, curved hero artwork, product-led photography, and clean spacing. These will be retained.

The actual product images must be separate assets. No buttons, headings, arrows, or navigation elements should be baked into images; Codex must build them as editable HTML components.

## 3. Recommended technical architecture

For a maintainable production website, I recommend Next.js + TypeScript + custom CSS, with PostgreSQL and Prisma for the catalogue, enquiries, stores, and blogs.

This gives you editable product records, dynamic URLs, a backend enquiry workflow, and a protected admin dashboard without adding online payment functionality.

## 4. Complete Codex development brief

The following specification is designed to be copied directly into Codex. It includes the site architecture, navigation, individual page requirements, products, CSS, functionality, database, and development workflow.

### Typography

- Headings: Playfair Display, with a Georgia fallback.
- Body content: DM Sans, with a sans-serif fallback.
- Serif headings combined with crisp sans-serif UI labels.
- Consistent responsive type sizes using CSS clamp().
- Readable body text, correct line heights, and appropriate contrast.

### Visual Elements

- Soft mint gradient backgrounds.
- White cards with subtle borders.
- Rounded product image containers.
- Teal buttons with hover states.
- Curved hero image boundaries.
- Light mint circular and wave decorations.
- Subtle gold accents only where aesthetically appropriate.
- Clean, organized product photography.
- Generous spacing between sections.
- Elegant product and article cards.
- Smooth, subtle transitions.
- Responsive grid layouts.

Avoid excessive animation and unnecessary visual effects.

### Layout Requirements

- Maximum content width approximately 1200px.
- Consistent side padding.
- Desktop: 4-column category grids where appropriate.
- Tablet: 2-column grids.
- Mobile: 1–2 columns according to available space.
- Desktop hero split layout: text on left, product image on right.
- Mobile hero: vertically stacked.
- Accessible, keyboard-friendly navigation.

### Image Handling

Use a separate `public/images` asset directory containing subdirectories for:

- brand
- hero
- categories
- subcategories
- products
- bulk
- stores
- blogs
- banners

Every image must be used through a reusable image component with proper alt text, responsive sizing, and object-fit settings.

Product images should show products only, without embedded website elements.

# 14. ENQUIRY FUNCTIONALITY

Enquire Now must work throughout the website.

It must be available from:

- Header where appropriate.
- Product cards.
- Product details.
- Category CTA sections.
- Homepage CTA.
- Contact page.
- Floating enquiry entry point if useful.

## Enquiry Fields

Required:

- Full Name.
- Mobile Number.
- Enquiry Type.
- Message or Requirement.

Optional:

- Email Address.
- City.
- Selected Category.
- Selected Product.
- Product Model.
- Quantity.

Automatically attach the product ID, product name, and page context when a product enquiry is initiated.

Enquiry Type options:

- Product Enquiry
- General Enquiry
- Store Enquiry
- Other

## Enquiry Submission Workflow

1. User clicks Enquire Now.
2. Form opens with applicable product details prefilled.
3. User enters contact details.
4. Client-side validation runs.
5. Server-side validation runs.
6. Submission is saved in the database.
7. Email notification is attempted.
8. User receives clear success confirmation.
9. Admin can review and manage the enquiry.

Use reliable error handling.

A notification failure must not silently lose a successfully saved enquiry.

Add bot and spam protection, reasonable rate limiting, and privacy consent.

Never claim a submission succeeded if database persistence failed.
